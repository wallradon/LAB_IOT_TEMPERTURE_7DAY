สรุปเป็นประโยคง่าย ๆ:

  1. ESP32 อ่านอุณหภูมิจากเซนเซอร์ DS18B20 ทุก 5 นาที (แล้วเข้าดีปสลีป)
  2. ESP32 ส่งค่าไปให้ Express API ด้วยคำสั่ง POST (เห็นได้ใน ESP/ESP.ino)
  3. Express API เอาค่าไป insert เข้าตาราง ชื่อ sensor_logs ใน Supabase (เห็นได้ใน server.js)
  4. Grafana เชื่อมต่อกับ Supabase ผ่าน connection string แล้ววาดกราฟจากข้อมูลในตาราง

2ดูโค้ดโปรเจคนี้ก่อน

เราต้องรู้ว่าข้อมูลถูกเก็บยังไงก่อน ถึงจะรู้ว่า Grafana ต้อง query ยังไง

2.1 ESP32 ส่งข้อมูลไปที่ไหน

ในไฟล์ ESP/ESP.ino ส่วนที่สำคัญที่สุดคือบรรทัดนี้ - บอก ESP32 ว่า "ไปส่งจดหมายที่ป้ายนี้":

// ESP/ESP.ino - บรรทัด 23
const char* SERVER_URL = "https://lab-iot-temperture-7day.onrender.com/api/temp";

แล้วส่งค่าอุณหภูมิในรูปแบบ JSON: {"temperature": 25.50}

2.2 Express API รับแล้วเก็บลง Supabase

ในไฟล์ server.js มี 2 ส่วนหลัก:

ส่วนที่ 1: สร้าง Supabase client (คีย์จากไฟล์ .env):

// server.js - บรรทัด 12-21
const supabaseUrl = process.env.SUPABASE_URL;
const supabaseKey = process.env.SUPABASE_PUBLISHABLE_KEY;
const supabase = createClient(supabaseUrl, supabaseKey);

ส่วนที่ 2: endpoint /api/temp เอา temperature ไป insert เข้าตาราง sensor_logs:

// server.js - บรรทัด 24-50
app.post('/api/temp', async (req, res) => {
  const { temperature } = req.body;
  const { data, error } = await supabase
    .from('sensor_logs')
    .insert([{ temperature: temperature }])
    .select();
  if (error) { return res.status(500).json({ error: 'Database server error' }); }
  res.status(201).json({ message: 'Temperature successfully saved to Supabase!' });
});

2.3 ขั้นตอนการสร้างฐานข้อมูลใน Supabase (Database Setup)

อ้างอิงขั้นตอนสร้างจากคู่มือ Refine - Supabase Database Setup Guide โดยมีขั้นตอนง่าย ๆ ดังนี้:

1สร้าง Project ใหม่บน Supabase

ไปที่ Supabase Dashboard แล้วกด New Project ตั้งชื่อโปรเจค (เช่น esp32-temp-monitoring), กำหนดรหัสผ่าน Database Password และเลือก Region (เช่น Singapore)

2สร้างตารางข้อมูล sensor_logs

ไปที่เมนู Table Editor ด้านซ้าย แล้วกด Create a new table ตั้งชื่อตารางว่า sensor_logs

3กำหนด Columns ให้ตาราง
ColumnTypeการตั้งค่าเพิ่มเติม / ความหมาย
idint8 / uuidตั้งเป็น Primary Key และเปิด Is Identity (Auto Increment)
temperaturefloat8 / numericค่าอุณหภูมิที่ส่งมาจาก ESP32
created_attimestamptzตั้งค่า Default Value เป็น now() เพื่อบันทึกเวลาอัตโนมัติ
4การตั้งค่าสิทธิ์ Row Level Security (RLS)

สามารถเลือกเปิด/ปิด RLS หรือกำหนด Policy เพื่อให้ Express API ของเราเข้าถึง (INSERT / SELECT) ข้อมูลได้ตามต้องการ

แหล่งอ้างอิงคู่มือสร้าง DB: สามารถอ่านรายละเอียดการตั้งค่าฐานข้อมูล Supabase เพิ่มเติมได้ที่ refine.dev/blog/supabase-database-setup/

3ทำความเข้าใจ API Keys & วิธีหาค่า Environment Variables

ก่อนนำ Node.js หรือแอปพลิเคชันใด ๆ ไปเชื่อมต่อกับ Supabase การเข้าใจเรื่อง API Keys (ด่านปราการความปลอดภัยชั้นแรก) ถือเป็นเรื่องสำคัญที่สุด

3.1 ทำความเข้าใจหน้าที่ของ API Keys (API Keys vs Supabase Auth)

API Key ทำหน้าที่ยืนยันตัวตนของ "แอปพลิเคชัน/คอมโพเนนต์" ที่เข้ามาใช้งาน Supabase (ไม่ได้แยกแยะว่าผู้ใช้คือใคร แต่บอกว่าระบบส่วนไหนกำลังอ่าน/เขียนข้อมูลอยู่)

หลักการเปรียบเทียบง่าย ๆ (ELI5):
• API Keys (ตอบคำว่า WHAT): "อะไร" กำลังเข้าถึงโปรเจค? (เช่น หน้าเว็บ, แอปมือถือ, เซิร์ฟเวอร์ Node.js หรือ Edge Function)
• Supabase Auth (ตอบคำว่า WHO): "ใคร" กำลังเข้าถึงโปรเจค? (เช่น คุณสมชาย, คุณสมหญิง, หรือ Admin)
ขอบเขตความรับผิดชอบ คำถามสำคัญ คำตอบ / ตัวอย่าง
API Keys What is accessing the project? Web page, Mobile app, Express Server, Edge Function...
Supabase Auth Who is accessing the project? User A, User B, Admin, Guest...

3.2 ประเภทของ API Keys ทั้ง 4 ชนิด (4 Types of API Keys)

Supabase มี API Keys ให้เลือกใช้ 4 ชนิด แบ่งตามระดับสิทธิ์ความปลอดภัยและรูปแบบคีย์ ดังนี้:

ประเภทคีย์ (Type) รูปแบบ (Format) ระดับสิทธิ์ การใช้งานที่เหมาะสม (Use Case)
Publishable key sb_publishable_... ต่ำ (Low) ปลอดภัยสำหรับเผยแพร่ออนไลน์: หน้าเว็บ Frontend, แอปมือถือ/คอมพิวเตอร์, GitHub Actions, CLI, ซอร์สโค้ดฝั่ง Client
Secret keys sb_secret_... สูงมาก (Elevated) ใช้เฉพาะฝั่ง Backend เท่านั้น: Express Server, Admin API, Edge Functions, Microservices คีย์นี้ข้ามผ่าน Row Level Security (RLS) ทั้งหมด!
anon (Legacy) JWT (Long lived) ต่ำ (Low) เวอร์ชันดั้งเดิมของ Publishable key (ยังใช้งานได้อยู่)
service_role (Legacy) JWT (Long lived) สูงมาก (Elevated) เวอร์ชันดั้งเดิมของ Secret key (ยังใช้งานได้อยู่)
📢 ประกาศการยกเลิกใช้งานคีย์แบบเก่า (Deprecation Notice):
Supabase ได้ปรับปรุงระบบ API Keys ใหม่เพื่อความปลอดภัยสูงสุด โดยคีย์แบบเก่าที่เป็น JWT (anon และ service_role) จะถูกยกเลิกการใช้งาน (Deprecated) ภายในสิ้นปี 2026 แนะนำให้เปลี่ยนมาใช้คีย์รูปแบบใหม่ sb_publishable_xxx และ sb_secret_xxx แทนในโปรเจคใหม่ทั้งหมด
หมายเหตุ: คีย์ทั้ง 2 รูปแบบสามารถทำงานร่วมกันได้พร้อมกัน และคีย์แบบเก่าจะยังคงใช้ได้จนกว่าจะกด Disable ใน Dashboard

3.3 รายละเอียดและการทำงานของ Publishable Keys

Publishable keys ใช้สำหรับส่วนของแอปพลิเคชันที่เป็น สาธารณะ (Public components) เช่น หน้าเว็บ HTML/React หรือแอปมือถือ ซึ่งเป็นไปไม่ได้ที่จะซ่อนกุญแจลับไว้ในซอร์สโค้ด

การทำงานร่วมกับ Supabase Auth & Postgres Roles:

API Key ที่ใช้ สถานะการ ล็อกอิน ผ่าน Supabase Auth Postgres Role ที่ใช้ตรวจสอบ RLS
Publishable key ยังไม่ได้ล็อกอิน (No) anon
Publishable key ล็อกอินแล้ว (Yes) authenticated
🛡️ ข้อพิจารณาด้านความปลอดภัยของ Publishable Keys:
ผู้ใช้ทั่วไปหรือผู้ไม่หวังดีสามารถดึงคีย์ Publishable ไปได้เสมอผ่าน F12 (Network Inspector) หรือการ Reverse Engineering ดังนั้นการป้องกันข้อมูลของ Supabase จึงขึ้นอยู่กับ Postgres Row Level Security (RLS)
• ต้องเปิดใช้งาน Row Level Security (RLS) บนทุกตารางเสมอ
• ตรวจสอบ RLS Policies ของบทบาท anon และ authenticated ให้รัดกุมอยู่เสมอ

3.4 ข้อควรระวังอย่างเข้มงวดและแนวทางปฏิบัติสำหรับ Secret Keys

Secret Key เปรียบเสมือน "กุญแจผี (Master Key)" เข้าถึงและแก้ไขฐานข้อมูลได้ทั้งหมดผ่าน Postgres Role service_role โดยจะ ข้ามการตรวจ RLS ทั้งหมด (BYPASSRLS)

คุณสมบัติพิเศษของ Secret Key ใหม่ (sb_secret_...):

  • หากนำ Secret Key ไปยิงผ่าน Web Browser โดยตรง ระบบ Supabase จะตรวจสอบ User-Agent และปฏิเสธคำขอทันทีด้วยข้อผิดพลาด HTTP 401 Unauthorized เพื่อป้องกันความผิดพลาด
⛔ ข้อห้ามเด็ดขาด (DO NOT):
  • ห้าม ใส่ Secret Key ในหน้าเว็บ, ซอร์สโค้ดฝั่ง Client, Public Document หรือ Bundle รวมในไฟล์ติดตั้งแอปมือถือ/Desktop
  • ห้าม ส่งคีย์ผ่านแอปแชต (Line, Discord), Email หรือ SMS
  • ห้าม ใช้งานผ่าน Web Browser แม้กระทั่งบน localhost
  • ห้าม ส่งคีย์ผ่าน URL หรือ Query Parameters (เนื่องจากมักถูกบันทึกใน Web Server Logs)
✅ แนวทางปฏิบัติที่ดี (Best Practices for Secret Keys):
  • ใช้งาน Secret Key บนเครื่อง Server หรือระบบ Backend ที่คุณเป็นผู้ดูแลและควบคุมเองเท่านั้น
  • จัดเก็บไว้ใน Environment Variables (ไฟล์ .env) และ ห้าม Commit เข้า Git Repository โดยเด็ดขาด
  • แยกใช้ Secret Key คนละดอกสำหรับแต่ละ Backend Component เพื่อจำกัดความเสียหายหากเกิดการรั่วไหล
  • หากจำเป็นต้องแสดงใน Log ให้ตัดแสดงเฉพาะ 6 ตัวอักษรแรกเท่านั้น หรือเก็บในรูปแบบ SHA256 Hash
  • หาก Secret Key รั่วไหล: ให้ไปที่ Dashboard → Settings > API Keys เพื่อสร้าง Secret Key ดอกใหม่ นำไปเปลี่ยนในระบบ Backend ให้เรียบร้อย แล้วทำการ Delete (ลบ) คีย์เก่าทิ้งทันที (การลบคีย์มีผลถาวร)

3.5 ข้อจำกัดและความแตกต่างที่ต้องรับมือ (Known Limitations)

  • การส่ง Header: ไม่สามารถส่ง Publishable หรือ Secret key ใน Authorization: Bearer ... ได้ เว้นแต่ค่านั้นจะตรงกับ apikey header ทุกประการ
  • Edge Functions: ปัจจุบัน Edge Functions รองรับการยืนยันตัวตน JWT ผ่านคีย์แบบเก่าเท่านั้น หากใช้ Publishable/Secret Key ใหม่ ต้องใส่ flag --no-verify-jwt และเขียนโค้ดเช็ก apikey header ภายใน Edge Function เอง
  • Realtime Connections: การเชื่อมต่อ Realtime แบบสาธารณะจะจำกัดระยะเวลาไว้ที่ 24 ชั่วโมง เว้นแต่จะมีการยืนยันตัวตนผู้ใช้ผ่าน Supabase Auth

3.6 ขั้นตอนการคัดลอกคีย์มาใส่ไฟล์ Environment Variables (.env) แบบรวดเร็ว

คุณสามารถก๊อปปี้ค่าทั้งหมดไปวางในไฟล์ .env ของโปรเจค Node.js Express ได้ง่าย ๆ ผ่านปุ่ม Connect ใน Supabase Dashboard ดังนี้:

1สร้างไฟล์ .env ในโปรเจค

สร้างไฟล์ชื่อ .env ไว้ที่โฟลเดอร์หลัก (Root Directory) ของโปรเจค Node.js Express ของคุณ

2เปิดหน้าต่าง Connect บน Supabase Dashboard

เข้า Supabase Dashboard เลือกโปรเจคของคุณ จากนั้นกดปุ่ม Connect (ปุ่มสีเขียวบริเวณแถบด้านบนของหน้าจอ)

3เลือกแท็บ App Frameworks / Server Build APIs

ในหน้าต่าง Connect ให้เลือกแท็บ App Frameworks หรือ Server / Build APIs

4คัดลอกค่าจากหัวข้อ Set environment variables

เลื่อนลงมาหาหัวข้อ Set environment variables (จะมีคำอธิบายระบุว่า "Copy these into your environment so your handler can verify users and use supabase-js")

คุณจะพบกล่องข้อความที่มีปุ่ม Copy Snippet / Copy All กดปุ่มนั้นแล้วนำข้อความทั้งหมดไปวาง (Paste) ในไฟล์ .env ได้ทันที!

ตัวอย่างรูปแบบค่าที่จะได้ในไฟล์ .env:

SUPABASE_URL=https://<your-project-id>.supabase.co SUPABASE_PUBLISHABLE_KEY=sb_publishable_... (หรือ anon JWT) SUPABASE_SECRET_KEY=sb_secret_... (หรือ service_role JWT - ใช้สำหรับ Node.js Backend) SUPABASE_JWKS_URL=https://<your-project-id>.supabase.co/auth/v1/.well-known/jwks.json
💡 ทางเลือกเพิ่มเติม (Project Settings): หากต้องการคัดลอกคีย์ทีละตัว หรือต้องการสร้าง Secret key ดอกใหม่ สามารถไปที่ Project Settings → API / API Keys เพื่อสร้างและคัดลอกค่าได้เช่นกัน
📚 แหล่งอ้างอิงเอกสาร API Keys: สามารถศึกษาเอกสารฉบับเต็มเพิ่มเติมได้ที่ Supabase Docs - Understanding API Keys

4การเชื่อมต่อ Supabase กับ Node.js (Express)

ในหัวข้อนี้เราจะอธิบายเบื้องหลังการทำงานว่า Node.js (Express) ของเราเชื่อมต่อและบันทึกข้อมูลไปยัง Supabase ได้อย่างไร

หลักการง่าย ๆ: Node.js ทำหน้าที่เป็น "บุรุษไปรษณีย์" ที่คอยรับอุณหภูมิมาจาก ESP32 แล้วนำไปหย่อนลงลิ้นชักตาราง sensor_logs ใน Supabase โดยใช้ library สำเร็จรูปชื่อ @supabase/supabase-js

4.1 การติดตั้ง Library ที่จำเป็น

ก่อนเริ่มต้น เราต้องลงไลบรารีสำหรับควบคุม Supabase และอ่านไฟล์ตั้งค่าสิ่งแวดล้อม (environment variables):

npm install @supabase/supabase-js dotenv

4.2 การกำหนดพิกัดความปลอดภัย (Environment Variables)

นำค่าคีย์ที่คัดลอกจากหัวข้อ 3 (โดยเฉพาะวิธีรวดเร็วจาก หัวข้อ 3.6 ผ่านปุ่ม Connect → Set environment variables → Copy Snippet) มาใส่ในไฟล์ .env ของโปรเจค ดังนี้:

SUPABASE_URL=https://klywhfmgmlicackbwuto.supabase.co
SUPABASE_PUBLISHABLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
SUPABASE_SECRET_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
SUPABASE_JWKS_URL=https://klywhfmgmlicackbwuto.supabase.co/auth/v1/.well-known/jwks.json

4.3 โค้ดเชื่อมต่อใน server.js

เมื่อนำไลบรารีมาประกอบเข้ากับไฟล์ตั้งค่า โค้ดในการเปิดประตูเชื่อมต่อจะมีหน้าตาดังนี้:

// server.js
const { createClient } = require('@supabase/supabase-js');

// 1. ดึงค่า URL และ KEY ลับมาจากไฟล์ .env
const supabaseUrl = process.env.SUPABASE_URL;
const supabaseKey = process.env.SUPABASE_PUBLISHABLE_KEY || process.env.SUPABASE_SECRET_KEY;

// 2. สร้าง Client สำหรับควบคุมฐานข้อมูล
const supabase = createClient(supabaseUrl, supabaseKey);

4.4 การนำข้อมูลใส่ลงตาราง (Insert Data)

เมื่อ ESP32 ยิงข้อมูลอุณหภูมิมาที่ POST /api/temp เราจะแกะค่า temperature ออกมา แล้วสั่ง Supabase Client นำค่านี้ไปบันทึก:

// server.js
app.post('/api/temp', async (req, res) => {
  const { temperature } = req.body;

  // ส่งข้อมูลไปบันทึกในตาราง 'sensor_logs'
  const { data, error } = await supabase
    .from('sensor_logs') // เลือกตาราง
    .insert([{ temperature: temperature }]) // ใส่ข้อมูลใหม่เป็น Array of Objects
    .select(); // คืนค่าข้อมูลแถวที่พึ่งจะเซฟกลับมาด้วย

  if (error) {
    console.error('Error:', error.message);
    return res.status(500).json({ error: 'Database error' });
  }

  res.status(201).json({ message: 'Saved successfully!', data });
});
เกร็ดความรู้เบื้องต้น: ฟังก์ชัน .from().insert() ของ Supabase คือการส่งข้อมูลแบบ HTTP Request ไปหาฐานข้อมูลของ Supabase เบื้องหลัง (เป็น REST API ที่เรียกกันว่า PostgREST) ทำให้เราไม่ต้องเขียนคำสั่ง SQL เพียว ๆ (เช่น INSERT INTO ...) ให้ยุ่งยากและยังมีความปลอดภัยสูง

5รู้จัก Connection String แบบ ELI5

Connection string คือ "ที่อยู่สำหรับไปอ่านกล่องจดหมาย" มันเป็นข้อความเดียวที่บอกว่า จะไปที่ไหน เข้าประตูไหน และใช้กุญแจอะไร (ต้องใช้ค่านี้ไปกรอกใน Grafana)

อุปมา: บ้านมีอยู่ 3 ประตู แต่ห้องข้อมูลเป็นห้องเดียวกัน
• Direct Connection = ไปเคาะประตูบ้านตรง ๆ (เร็ว แต่ถ้าหลายคนใช้พร้อมกัน รถติด)
• Transaction Pooler = มีคุณลุงหน้าประตูคอยจัดการคิว ใครจะเข้าขอเข้า (เหมาะสมกับหลายการเชื่อมต่อ)
• Session Pooler = เหมือน Transaction แต่เก็บที่นั่งให้ทั้งคอนเสิร์ต (Grafana ไม่ค่อยได้ใช้แบบนี้)

5.1 ไปเอาที่อยู่ (Connection String) มาจากไหน

💡 คำแนะนำพิเศษ: สำหรับ Grafana แนะนำให้เลือก Connection Method เป็น Transaction pooler (พอร์ต 6543) เป็นหลัก เพราะช่วยคุมคิวและจัดการการเชื่อมต่อได้ดีที่สุด ไม่เกิดปัญหา Connection เต็ม (too many clients)

วิธีคัดลอกผ่านหน้าต่าง Connect (เร็วที่สุดและแนะนำ):

1เปิดหน้าต่าง Connect

เข้า Supabase Dashboard เลือกโปรเจคของคุณ แล้วกดปุ่ม Connect สีเขียวบริเวณแถบด้านบน (เช่นเดียวกับหัวข้อ 3.6)

2เลือกแท็บ Direct Connection string

ในหน้าต่าง Connect ให้คลิกเลือกแท็บ Direct Connection string (หรือ Database Connection)

3ตั้งค่า Connection Method & Type
  • Connection Method: เลือกเป็น Transaction pooler (แนะนำที่สุดสำหรับ Grafana)
  • Type: เลือกเป็น URI หรือ Parameters
4ดูข้อมูลพารามิเตอร์ที่ได้จาก Supabase

Supabase จะแสดงค่าพารามิเตอร์การเชื่อมต่อแยกออกเป็นหัวข้อด้านล่าง ดังนี้:

host=aws-0-ap-northeast-1.pooler.supabase.com port=6543 database=postgres user=postgres.klywhfmgmlicackbwuto password=[กดรูปดวงตาเพื่อดูรหัสผ่าน DB]

5.2 วิธีผสมข้อมูล (Combining Parameters) สำหรับ Grafana

เมื่อได้ค่าพารามิเตอร์ทั้ง 5 ตัวมาจากขั้นตอน 5.1 แล้ว นำมาผสมใช้งานได้ 2 รูปแบบดังนี้:

แบบที่ 1: ผสมเป็น Connection String (URI Format)

ใช้สูตรผสมโครงสร้าง: postgresql://[user]:[password]@[host]:[port]/[database]

postgresql://postgres.klywhfmgmlicackbwuto:YOUR_DB_PASSWORD@aws-0-ap-northeast-1.pooler.supabase.com:6543/postgres

แบบที่ 2: ผสมและนำไปใส่ช่องตั้งค่าใน Grafana Data Source (หัวข้อ 6.2)

ช่องใน Grafana สูตรการนำค่ามาผสมใส่ ตัวอย่างค่าจริง
Host นำ host มาต่อด้วย :port aws-0-ap-northeast-1.pooler.supabase.com:6543
Database ใส่ค่า database ตรง ๆ postgres
User ใส่ค่า user ตรง ๆ postgres.klywhfmgmlicackbwuto
Password ใส่รหัสผ่าน DB ที่กดดูจากไอคอนดวงตา รหัสผ่าน DB ของคุณ
TLS/SSL Mode เลือก require เสมอ require

5.3 รูปแบบของ Connection String ทั้ง 3 แบบ (เปรียบเทียบ Port)

ในการใช้งานทั่วไป Connection String ของ Supabase จะมี 3 ประเภทหลัก ดังนี้:

Direct Connection (พอร์ต 5432):

postgresql://postgres.klywhfmgmlicackbwuto:YOUR_DB_PASSWORD@db.klywhfmgmlicackbwuto.supabase.co:5432/postgres

Transaction Pooler (พอร์ต 6543 - แนะนำสำหรับ Grafana):

postgresql://postgres.klywhfmgmlicackbwuto:YOUR_DB_PASSWORD@aws-0-ap-northeast-1.pooler.supabase.com:6543/postgres

Session Pooler (พอร์ต 5432):

postgresql://postgres.klywhfmgmlicackbwuto:YOUR_DB_PASSWORD@aws-0-ap-northeast-1.pooler.supabase.com:5432/postgres
แบบPortเหมาะกับควรใช้กับ Grafana?
Direct5432เครื่องมือเดียว เชื่อมน้อยครั้งใช่ เหมาะสุดถ้าปิด pooler ได้
Transaction Pooler6543หลาย connection พร้อมกันใช่ ตัวที่แนะนำ
Session Pooler5432ต้องการ session เดิมตลอดไม่ค่อยจำเป็น
ข้อระวังเรื่องรหัสผ่าน: รหัสผ่าน DB Password เป็นกุญแจสำคัญ ห้ามแปะไว้ในซอร์สโค้ดหรือ commit ลง GitHub โดยเด็ดขาด

8ปัญหาเจอบ่อย + วิธีแก้

เจอปัญหาติดขัด ตรวจสอบทีละข้อได้ดังนี้:

อาการสาเหตุที่เป็นไปได้วิธีแก้
Save & Test เจอ "dial error / timeout" ใส่พอร์ตผิด หรือใช้ Direct connection แต่ IP ไม่ได้ allow ลอง Transaction Pooler พอร์ต 6543 ก่อน ถ้าจะใช้ Direct ให้เปิด Direct Connection (allow IP) ที่อยู่ในการตั้งค่า database ของโปรเจค
"SSL error" หรือ "no pg_hba.conf entry" TLS ยังไม่ require หรือ username ผิดรูปแบบ ตั้ง SSL Mode = require และ User ต้องเป็น postgres.<project-ref> แบบเต็ม
เชื่อมต่อได้ แต่ panel ว่างเปล่า Query ผิด หรือไม่มีข้อมูลในช่วงเวลาที่เลือก ลอง query ง่าย ๆ: select count(*) from sensor_logs; แล้วลองกดช่วงเวลา "Last 24 hours"
"column created_at does not exist" ตารางไม่มีคอลัมน์เวลา ไปเพิ่มคอลัมน์ created_at timestamptz default now() ใน Table Editor
"too many clients" ใช้ Direct connection ที่จำกัด 60 connections และ Grafana เปิดซ้ำ ๆ สลับไปใช้ Transaction Pooler (6543) ซึ่งจัดการคิวให้เอง
Grafana เห็นแต่ข้อมูลเก่า Refresh interval ช้ากว่ารอบการส่งข้อมูลของ ESP32 ตั้ง Refresh = 5m และช่วงเวลาให้ครอบคลุมหลาย ๆ ชั่วโมง
