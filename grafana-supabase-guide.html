สรุปเป็นประโยคง่าย ๆ:

  1. ESP32 อ่านอุณหภูมิจากเซนเซอร์ DS18B20 ทุก 5 นาที (แล้วเข้าดีปสลีป)
  2. ESP32 ส่งค่าไปให้ Express API ด้วยคำสั่ง POST (เห็นได้ใน ESP/ESP.ino)
  3. Express API เอาค่าไป insert เข้าตาราง ชื่อ sensor_logs ใน Supabase (เห็นได้ใน server.js)
  4. Grafana เชื่อมต่อกับ Supabase ผ่าน connection string แล้ววาดกราฟจากข้อมูลในตาราง

2ดูโค้ดโปรเจคนี้ก่อน

เราต้องรู้ว่าข้อมูลถูกเก็บยังไงก่อน ถึงจะรู้ว่า Grafana ต้อง query ยังไง

2.1 ESP32 ส่งข้อมูลไปที่ไหน

ในไฟล์ ESP/ESP.ino ส่วนที่สำคัญที่สุดคือบรรทัดนี้ - บอก ESP32 ว่า "ไปส่งจดหมายที่ป้ายนี้":

// ESP/ESP.ino - บรรทัด 23
const char* SERVER_URL = "https://lab-iot-temperture-7day.onrender.com/api/temp";

แล้วส่งค่าอุณหภูมิในรูปแบบ JSON: {"temperature": 25.50}

2.2 Express API รับแล้วเก็บลง Supabase

ในไฟล์ server.js มี 2 ส่วนหลัก:

ส่วนที่ 1: สร้าง Supabase client (คีย์จากไฟล์ .env):

// server.js - บรรทัด 12-21
const supabaseUrl = process.env.SUPABASE_URL;
const supabaseKey = process.env.SUPABASE_PUBLISHABLE_KEY;
const supabase = createClient(supabaseUrl, supabaseKey);

ส่วนที่ 2: endpoint /api/temp เอา temperature ไป insert เข้าตาราง sensor_logs:

// server.js - บรรทัด 24-50
app.post('/api/temp', async (req, res) => {
  const { temperature } = req.body;
  const { data, error } = await supabase
    .from('sensor_logs')
    .insert([{ temperature: temperature }])
    .select();
  if (error) { return res.status(500).json({ error: 'Database server error' }); }
  res.status(201).json({ message: 'Temperature successfully saved to Supabase!' });
});

2.3 ขั้นตอนการสร้างฐานข้อมูลใน Supabase (Database Setup)

อ้างอิงขั้นตอนสร้างจากคู่มือ Refine - Supabase Database Setup Guide โดยมีขั้นตอนง่าย ๆ ดังนี้:

1สร้าง Project ใหม่บน Supabase

ไปที่ Supabase Dashboard แล้วกด New Project ตั้งชื่อโปรเจค (เช่น esp32-temp-monitoring), กำหนดรหัสผ่าน Database Password และเลือก Region (เช่น Singapore)

2สร้างตารางข้อมูล sensor_logs

ไปที่เมนู Table Editor ด้านซ้าย แล้วกด Create a new table ตั้งชื่อตารางว่า sensor_logs

3กำหนด Columns ให้ตาราง
ColumnTypeการตั้งค่าเพิ่มเติม / ความหมาย
idint8 / uuidตั้งเป็น Primary Key และเปิด Is Identity (Auto Increment)
temperaturefloat8 / numericค่าอุณหภูมิที่ส่งมาจาก ESP32

4การตั้งค่าสิทธิ์ Row Level Security (RLS)

สามารถเลือกเปิด/ปิด RLS หรือกำหนด Policy เพื่อให้ Express API ของเราเข้าถึง (INSERT / SELECT) ข้อมูลได้ตามต้องการ

แหล่งอ้างอิงคู่มือสร้าง DB: สามารถอ่านรายละเอียดการตั้งค่าฐานข้อมูล Supabase เพิ่มเติมได้ที่ refine.dev/blog/supabase-database-setup/

3การเชื่อมต่อ Supabase กับ Node.js (Express)

ในหัวข้อนี้เราจะอธิบายเบื้องหลังการทำงานว่า Node.js (Express) ของเราเชื่อมต่อและบันทึกข้อมูลไปยัง Supabase ได้อย่างไร

หลักการง่าย ๆ: Node.js ทำหน้าที่เป็น "บุรุษไปรษณีย์" ที่คอยรับอุณหภูมิมาจาก ESP32 แล้วนำไปหย่อนลงลิ้นชักตาราง sensor_logs ใน Supabase โดยใช้ library สำเร็จรูปชื่อ @supabase/supabase-js

3.1 การติดตั้ง Library ที่จำเป็น

ก่อนเริ่มต้น เราต้องลงไลบรารีสำหรับควบคุม Supabase และอ่านไฟล์ตั้งค่าสิ่งแวดล้อม (environment variables):

npm install @supabase/supabase-js dotenv

3.2 การกำหนดพิกัดความปลอดภัย (Environment Variables)

ในไฟล์ .env ของโปรเจค เราจะเก็บ URL และ Key ลับไว้เพื่อป้องกันความปลอดภัย โดยมีหน้าตาประมาณนี้:

SUPABASE_URL=https://klywhfmgmlicackbwuto.supabase.co
SUPABASE_PUBLISHABLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

3.3 โค้ดเชื่อมต่อใน server.js

เมื่อนำไลบรารีมาประกอบเข้ากับไฟล์ตั้งค่า โค้ดในการเปิดประตูเชื่อมต่อจะมีหน้าตาดังนี้:

// server.js
const { createClient } = require('@supabase/supabase-js');

// 1. ดึงค่า URL และ KEY ลับมาจากไฟล์ .env
const supabaseUrl = process.env.SUPABASE_URL;
const supabaseKey = process.env.SUPABASE_PUBLISHABLE_KEY;

// 2. สร้าง Client สำหรับควบคุมฐานข้อมูล
const supabase = createClient(supabaseUrl, supabaseKey);

3.4 การนำข้อมูลใส่ลงตาราง (Insert Data)

เมื่อ ESP32 ยิงข้อมูลอุณหภูมิมาที่ POST /api/temp เราจะแกะค่า temperature ออกมา แล้วสั่ง Supabase Client นำค่านี้ไปบันทึก:

// server.js
app.post('/api/temp', async (req, res) => {
  const { temperature } = req.body;

  // ส่งข้อมูลไปบันทึกในตาราง 'sensor_logs'
  const { data, error } = await supabase
    .from('sensor_logs') // เลือกตาราง
    .insert([{ temperature: temperature }]) // ใส่ข้อมูลใหม่เป็น Array of Objects
    .select(); // คืนค่าข้อมูลแถวที่พึ่งจะเซฟกลับมาด้วย

  if (error) {
    console.error('Error:', error.message);
    return res.status(500).json({ error: 'Database error' });
  }

  res.status(201).json({ message: 'Saved successfully!', data });
});
เกร็ดความรู้เบื้องต้น: ฟังก์ชัน .from().insert() ของ Supabase คือการส่งข้อมูลแบบ HTTP Request ไปหาฐานข้อมูลของ Supabase เบื้องหลัง (เป็น REST API ที่เรียกกันว่า PostgREST) ทำให้เราไม่ต้องเขียนคำสั่ง SQL เพียว ๆ (เช่น INSERT INTO ...) ให้ยุ่งยากและยังมีความปลอดภัยสูง

7ปัญหาเจอบ่อย + วิธีแก้

เจอ "คุณลุงไปกล่องจดหมายไม่ได้" ตรวจทีละข้อ

อาการสาเหตุที่เป็นไปได้วิธีแก้
Save & Test เจอ "dial error / timeout" ใส่พอร์ตผิด หรือใช้ Direct connection แต่ IP ไม่ได้ allow ลอง Transaction Pooler พอร์ต 6543 ก่อน ถ้าจะใช้ Direct ให้กดปุ่ม Connect แล้วเปิด Direct Connection (allow IP) ที่อยู่ในการตั้งค่า database ของโปรเจค แล้ว allow IP ของเครื่อง/เซิร์ฟเวอร์ Grafana
"SSL error" หรือ "no pg_hba.conf entry" TLS ยังไม่ require หรือ username ผิดรูปแบบ ตั้ง SSL Mode = require และ User ต้องเป็น postgres.<project-ref> แบบเต็ม
เชื่อมต่อได้ แต่ panel ว่างเปล่า Query ผิด หรือไม่มีข้อมูลในช่วงเวลาที่เลือก ลอง query ง่าย ๆ: select count(*) from sensor_logs; แล้วลองกดช่วงเวลา "Last 24 hours"
"column created_at does not exist" ตารางไม่มีคอลัมน์เวลา ไปเพิ่มคอลัมน์ created_at timestamptz default now() ใน Table Editor
"too many clients" ใช้ Direct connection ที่จำกัด 60 connections และ Grafana เปิดซ้ำ ๆ สลับไปใช้ Transaction Pooler (6543) ซึ่งจัดการคิวให้เอง
Grafana เห็นแต่ข้อมูลเก่า Refresh interval ช้ากว่ารอบการส่งข้อมูลของ ESP32 ตั้ง Refresh = 5m และช่วงเวลาให้ครอบคลุมหลาย ๆ ชั่วโมง

8รู้จัก Connection String แบบ ELI5

Connection string คือ "ที่อยู่สำหรับไปอ่านกล่องจดหมาย" มันเป็นข้อความเดียวที่บอกว่า จะไปที่ไหน เข้าประตูไหน และใช้กุญแจอะไร

อุปมา: บ้านมีอยู่ 3 ประตู แต่ห้องข้อมูลเป็นห้องเดียวกัน
• Direct Connection = ไปเคาะประตูบ้านตรง ๆ (เร็ว แต่ถ้าหลายคนใช้พร้อมกัน รถติด)
• Transaction Pooler = มีคุณลุงหน้าประตูคอยจัดการคิว ใครจะเข้าขอเข้า (เหมาะสมกับหลายการเชื่อมต่อ)
• Session Pooler = เหมือน Transaction แต่เก็บที่นั่งให้ทั้งคอนเสิร์ต (Grafana ไม่ค่อยได้ใช้แบบนี้)

8.1 ไปเอาที่อยู่มาจากไหน

💡 คำแนะนำพิเศษ: สำหรับ Grafana แนะนำให้เลือกประเภท Transaction Pooler (พอร์ต 6543) เป็นหลัก เพราะช่วยคุมคิวและจัดการการเชื่อมต่อได้ดีที่สุด ไม่เกิดปัญหา Connection เต็ม (too many clients)

วิธีที่ 1 (เร็วที่สุดและแนะนำ): ใช้ปุ่ม Connect ที่หน้าโปรเจค

  1. เข้า Supabase Dashboard
  2. เลือกโปรเจคของคุณ
  3. กดปุ่ม Connect สีเขียวตรงกลางจอด้านบน (ในหน้า Overview/Home ของโปรเจค)
  4. ระบบจะให้เลือกว่าเป็น Connection แบบไหน ให้เลือก Transaction (แนะนำสุด) หรือ Direct
  5. จากนั้นเลือกประเภท URI แล้วคัดลอกข้อความมาใช้งาน

วิธีที่ 2 (ทางเมนู): ใช้เมื่อหาเมนู Connect ไม่เจอ

  1. ไป Project Settings (มุมขวาล่างของหน้าจอ)
  2. เมนูปัจจุบันของ Supabase จะเป็นแบบนี้: Settings → Configuration → General / Infrastructure / Integrations, API Keys, JWT Keys, Data API, Vault ฯลฯ (UI เปลี่ยนไปเรื่อย ๆ)
  3. ที่อยู่ของฐานข้อมูล (host/port) และปุ่มแสดงรหัสผ่านจะอยู่ในส่วนที่เกี่ยวข้องกับฐานข้อมูล เช่น Configuration → Infrastructure หรือหน้า Connect — เลือกข้อมูล Connection String ของ Transaction Pooler

8.2 รูปแบบของ Connection String ทั้ง 3 แบบ

โครงสร้าง: postgresql://ผู้ใช้:รหัสผ่าน@ที่อยู่:port/ชื่อฐานข้อมูล

Direct Connection (พอร์ต 5432):

postgresql://postgres.klywhfmgmlicackbwuto:YOUR_DB_PASSWORD@db.klywhfmgmlicackbwuto.supabase.co:5432/postgres

Transaction Pooler (พอร์ต 6543):

postgresql://postgres.klywhfmgmlicackbwuto:YOUR_DB_PASSWORD@aws-0-ap-southeast-1.pooler.supabase.com:6543/postgres

Session Pooler (พอร์ต 5432):

postgresql://postgres.klywhfmgmlicackbwuto:YOUR_DB_PASSWORD@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres
แบบPortเหมาะกับควรใช้กับ Grafana?
Direct5432เครื่องมือเดียว เชื่อมน้อยครั้งใช่ เหมาะสุดถ้าปิด pooler ได้
Transaction Pooler6543หลาย connection พร้อมกันใช่ ตัวที่แนะนำ
Session Pooler5432ต้องการ session เดิมตลอดไม่ค่อยจำเป็น

8.3 ค้นหา Database Password

  1. กดปุ่ม Connect สีเขียวที่หน้าโปรเจค (เหมือนหัวข้อ 7.1 วิธีที่ 1)
  2. เลือกรูปแบบ URI หรือ Connection string จะมีปุ่มแสดงรหัสผ่าน (eye icon) กดเพื่อดู
  3. นำรหัสไปแทนที่ YOUR_DB_PASSWORD ในช่องบน ๆ
ระวัง! รหัสผ่านนี้เป็นของจริง อย่าเอาไปแปะในโค้ดหรือ commit ลง GitHub เก็บไว้ใน Grafana เป็น Secret ดีกว่า (ดูหัวข้อ 5) และแนะนำให้สร้าง Database Password แยก จากการตั้งค่า "Direct Connection" ที่ allow IP แค่วง LAN ของคุณ เพื่อกันคนอื่นงัดกล่องจดหมาย

8.4 ตรวจสอบก่อนเชื่อม (บนเครื่องเรา)

ลองทดสอบว่าที่อยู่นี้ใช้ได้หรือยัง ด้วยคำสั่ง (ถ้ามี psql):

psql "postgresql://postgres.klywhfmgmlicackbwuto:YOUR_DB_PASSWORD@aws-0-ap-southeast-1.pooler.supabase.com:6543/postgres" -c "select count(*) from sensor_logs;"

ถ้าได้ตัวเลขกลับมา แปลว่าที่อยู่ถูกต้องแล้ว เราพร้อมไปหา Grafana ต่อ!

9สรุป + ตารางคำศัพท์

สรุปแบบกระชับ

  1. ESP32 วัดอุณหภูมิ → ส่ง {"temperature": xx} ไป /api/temp
  2. Express เก็บลงตาราง sensor_logs ใน Supabase (รายละเอียดเพิ่มเติมอยู่ในหัวข้อ 3)
  3. เปิด Grafana → Add Data source → PostgreSQL
  4. กรอก host/password จาก connection string (แนะนำ Transaction Pooler พอร์ต 6543, SSL require)
  5. สร้าง Dashboard พร้อม SQL query แล้วจบ!

ตารางคำศัพท์ (จดไว้ก่อนสอบ)

คำศัพท์ELI5ในโปรเจคนี้
APIพนักงานรับจดหมายที่รับคำสั่งแล้วไปทำงานให้POST /api/temp ใน server.js
Databaseตู้เอกสารยักษ์ที่เก็บจดหมายทุกฉบับSupabase (PostgreSQL)
Tableชั้นในตู้เอกสารที่เก็บเรื่องเดียวsensor_logs
Connection stringที่อยู่ + กุญแจของตู้เอกสารข้อความในหัวข้อ 7.2
Direct Connectionประตูบ้านตรง ๆ ไม่มีคนคุมคิวพอร์ต 5432, host db.*.supabase.co
Transaction Poolerคุณลุงหน้าประตูจัดการคิว (เหมาะกับ Grafana)พอร์ต 6543, host *.pooler.supabase.com
SSLซองจดหมายล็อกลับเฉพาะคนสองคนอ่านได้ต้องเปิด require เสมอ
Queryคำถามที่ถามตู้เอกสารว่า "เอาข้อมูลแบบไหน"SQL ในหัวข้อ 6
Dashboardผนังห้องที่ติดกราฟรูปสวยหลาย ๆ อันสิ่งที่เราสร้างในหัวข้อ 6
